# AI Mock V2 人工标注与仲裁协议 v1

## 1. 证据边界

`ai-mock-v2-legacy@1.0.0` 的 318 条样本中，314 条来自确定性模板生成，4 条是历史 curated reference。`referenceScore` 只用于工程回归，不属于人工 Gold；在两名标注员独立完成且分歧处理前，不得报告“与人工评分一致率”。

## 2. 角色与盲法

- 每条进入人工校准的样本由 `PRIMARY`、`SECONDARY` 两名标注员独立完成。
- 同一样本的三个角色必须使用不同别名；每个角色只能有一人，完成仲裁后前两份标注锁定。
- 标注员只使用去身份化别名（例如 `ann-a01`），不得把姓名、邮箱写入评测库。
- 标注界面或任务包不得显示 `referenceScore`、模型输出、另一位标注结果或线上用户身份。
- 需要仲裁时，由未参加前两轮的 `ARBITRATOR` 查看两份标注、证据与分歧原因。

## 3. 必填字段

| 字段 | 规则 |
| --- | --- |
| 四维分 | STAR/模块完整性、逻辑结构、内容深度、表达质量；每项 1–5 整数 |
| 总分 | 0–100 整数；标注员按固定 Rubric 综合确认 |
| 证据引用 | 至少一个回答片段定位，例如 `answer:L1-L2:缺少个人职责`；不得补造事实 |
| 追问动作 | `DEEPEN / CHALLENGE / NEXT / STOP`，无需追问时选 `STOP` |
| 说明 | 只解释扣分、证据缺口或风险，不复制无关敏感信息 |

## 4. 评分锚点

- 1：缺失或严重错误，无法支撑面试判断。
- 2：有零散信息，但关键角色、逻辑或证据明显不足。
- 3：基本完整，可理解，但缺少关键量化、验证、取舍或反思。
- 4：结构清晰、证据充分，只有局部可改进项。
- 5：完整、可核验、表达紧凑，并主动说明假设、风险或失效条件。

技术、市场题的“完整性”按模块 Rubric 判断，不强制套用 STAR。标注员只能评价回答中实际出现的内容，不能因常识上“可能如此”而加分。

## 5. 追问动作

- `DEEPEN`：主题相关，但缺少指标口径、验证、机制、取舍或关键证据。
- `CHALLENGE`：答非所问、所有权含糊、事实冲突或需要澄清。
- `NEXT`：当前问题已达到可接受完整度，转到下一题。
- `STOP`：达到轮次上限、已完整结束，或安全策略要求停止。

## 6. 仲裁规则

以下任一条件触发第三人仲裁：

- 任一维度分差大于 1；
- 总分差大于 10；
- 追问动作不一致；
- 任一标注缺少证据或违反盲法。

两份独立标注一致时状态为 `DOUBLE_BLIND_COMPLETE`；完成第三人仲裁后为 `ARBITRATED`。只完成一份或存在未处理分歧时保持 `DOUBLE_BLIND_PENDING`。

## 7. 执行命令

先验证冻结集：

```powershell
npm.cmd run eval:dataset:verify
```

录入一份标注：

```powershell
npm.cmd run eval:annotate -- <sampleKey> <ann-alias> <PRIMARY|SECONDARY|ARBITRATOR> <0-100> <star1-5> <logic1-5> <depth1-5> <communication1-5> <DEEPEN|CHALLENGE|NEXT|STOP|NONE> <evidence-ref[,evidence-ref]> [notes]
```

脚本会验证字段、检查冻结版本、计算分歧并更新样本标注状态；输出不包含原始回答。

## 8. 报告规则

- 至少分别报告 category、module、role 与 TEST split，不以总体平均掩盖薄弱切片。
- 自动 Gate、legacy reference 对齐率、双盲人工一致率必须分开。
- 人工 Gold 数为 0 时，人工一致率写 `PENDING/null`，不得写 0% 或 100%。
- 任何模型、Prompt、Rubric 或检索变更都使用同一冻结版本比较；修改样本或标签必须创建新版本。
