# AI Mock V2 最小试点研究包

> 状态：工程与研究材料就绪，真实参与者、日期和结果均待执行。任何空白不得用种子数据或开发者自测代填。

## 1. 研究问题与样本

最危险假设：目标用户愿意在反馈后立即重答，并认为“弱点被等价题复测”比只完成一次逼真 Mock 更有价值。

- 建议首轮招募 5～8 名正在准备 AI 产品实习/校招、已有项目经历的候选人；最终人数、渠道和周期由负责人确认。
- 每人完成材料事实确认、3～5 题 Mock、至少一次立即重答、7 日内一次等价题复测和 10～15 分钟回访。
- 不把内部成员自测纳入产品效果分母；如需记录，应标为 `internal_dogfood` 并单独分析。

## 2. 知情说明（开始前逐字展示）

本次测试用于评估 AI Mock 的训练流程，不是招聘评估。系统会保存你主动提交的简历/项目材料、回答、评分、交互事件和脱敏运行记录，用于定位问题和改进产品。AI 反馈可能不准确，请不要提交身份证号、账号密钥或未获授权的公司机密。你可以跳过任何问题，并可在账户页修正/删除 Memory 或永久删除账户数据。研究记录仅按参与者编号分析，不对外公开原始简历和回答。继续前，请确认你已理解并自愿参加。

记录字段：`consent_at`、`participant_ref`、`cohort`、`researcher`。未确认知情说明不得开始任务。

## 3. 主持任务脚本

1. 请上传材料，并逐条确认、修改或拒绝系统抽取的项目事实；观察哪些事实让你犹豫。
2. 完成一场 3～5 题 Mock。主持人不解释评分逻辑，只记录卡点和退出位置。
3. 打开报告，选择你认为最重要的一条反馈，立即重答同一题。
4. 查看前后对比，口述哪些建议被采用、哪些没有，以及原因。
5. 确认一个弱点和复测日期。7 日内完成系统给出的等价题。
6. 完成回访，不向参与者暗示“分数应该提高”。

## 4. 回访问题

1. 哪一条反馈最准确？请指出回答中的具体证据。
2. 哪一条反馈你不信任或无法执行？为什么？
3. 重答时你具体改变了什么？这个变化来自系统还是你原本就知道？
4. 等价题是否真的在测试同一能力，而不是重复原题？
5. 复测时你有没有主动使用上次的方法？
6. 如果下周有真实面试，你会再次使用哪一部分？不会使用哪一部分？
7. Memory 中是否存在错误、越界归因或你不希望长期保存的内容？

## 6. 事件与导出

固定事件：`mock_start`、`mock_complete`、`report_view`、`retry_started`、`retry_completed`、`feedback_adopted`、`plan_created`、`retest_completed`。服务端写事件，外部事件 API 只接受白名单、登录用户和本人 Session。

导出命令：

```powershell
npm.cmd run pilot:export -- 2026-08-18T00:00:00+08:00 2026-08-26T00:00:00+08:00
```

导出仅含聚合、哈希参与者引用和 Trace 健康度；分母为 0 时比率返回 `null`，不得写成 0% 或 100%。

解释规则：不进入重答，优先降低任务成本或重做反馈呈现；重答多但无改善，检查反馈/Rubric/Judge；立即改善但复测失败，强化间隔训练；检索并非主要问题时，暂缓扩大面经库。这些是预先规则，不是已观察结论。

## 8. 停止与升级条件

- 出现跨用户数据、原始回答进入 Trace、未授权面经发布或账户删除不完整：立即停止试点。
- 连续出现评分/Tool 超时或成本上限触发：切回本地 Rubric/审核题库并登记 Trace。
- 参与者要求退出：停止采集并按其选择删除账户或研究记录。
